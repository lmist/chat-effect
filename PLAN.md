**Goal:** Ship a working Next.js App Router web chat at the repository root that uses Chat SDK (`chat`) + `@chat-adapter/web`, kit-derived shadcn chat UI, and an XState v5 conversation machine; `npm run build` must pass; deploy with `vercel --yes --prod` as project `chat-effect`.

**Architecture:** The browser talks only to `POST /api/chat` through `@chat-adapter/web/react` `useChat` (AI SDK UI message stream). That webhook is `bot.webhooks.web`. Every browser turn is a Chat SDK DM and lands in `onDirectMessage`. The handler either streams a deterministic echo or, when `XAI_API_KEY` is set, `streamText` + `toAiMessages` + `thread.post(textStream)`. XState owns client session UX (`idle` / `sending` / `streaming` / `stopped` / `error`). Chat SDK remains the server authority for messages and streaming.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind v4, shadcn tokens, `chat@^4.38.0` (already installed), `@chat-adapter/web`, `@chat-adapter/state-memory`, `ai` + `@ai-sdk/react` + `@ai-sdk/xai`, `xstate` + `@xstate/react`.

## How the pieces fit

```
Browser
  components/chat-shell.tsx
    useChatSession()
      useChat({ api: "/api/chat", threadId })     // @chat-adapter/web/react
      useMachine(chatMachine)                     // XState v5
      sendMessage / stop / regenerate             // hook
      SUBMIT / TOKEN / DONE / FAIL / STOP / RETRY // machine
        │
        ▼ POST { id, messages: UIMessage[] }
app/api/chat/route.ts
  bot.webhooks.web(request, { waitUntil: after })
        │
        ▼ getUser → threadId = web:web-user:{conversationId}
        ▼ every web turn is a DM
lib/bot.ts  bot.onDirectMessage
  no XAI_API_KEY → thread.post(echoTextStream(message.text))
  XAI_API_KEY    → toAiMessages(history) → streamText → thread.post(textStream)
        │
        ▼ SSE UI message stream (createUIMessageStream)
useChat updates messages + status
machine callbacks fire TOKEN / DONE / FAIL
```

Threading (from `@chat-adapter/web`):

- Client `useChat({ threadId })` becomes the request body’s `id` (conversation id).
- Server default: `web:{user.id}:{conversationId}`.
- “New conversation” generates a new conversation id and remounts the session with `key={threadId}` so both hook and machine start clean.

History for xAI:

- `persistMessageHistory` stays at the default `true`.
- Web `fetchMessages` itself returns `[]`; Chat SDK’s `MessageHistoryCache` backfills `thread.messages` / `thread.allMessages` from memory state.
- Memory state is per-process. On Vercel serverless that cache will often be empty after a cold start. Still call `toAiMessages` on whatever `thread.allMessages` yields, and if the converted list is empty, pass `[{ role: "user", content: message.text }]`. The product still works.

## XState v5 machine

Package: `xstate` + `@xstate/react`. Machine lives in `lib/chat-machine.ts`. UI never inspects a pile of booleans for session phase; it reads `snapshot.matches(...)`.

**Context**

- `threadId: string`
- `lastError: string | null`
- `abortable: boolean`

**States** (required): `idle` → `sending` → `streaming` → `idle`, plus `stopped` and `error`.

**Events** (required): `SUBMIT`, `TOKEN`, `DONE`, `FAIL`, `STOP`, `RETRY`.

```
                  SUBMIT
   ┌──────────────────────────────────────────┐
   │                                          │
 idle ──SUBMIT──► sending ──TOKEN──► streaming
   ▲                 │  │                │  │
   │            DONE─┘  │           DONE─┘  │
   │            STOP────┼──► stopped        │
   │            FAIL────┼──► error          │
   │                    │         │         │
   │                    └─────────┴─────────┘
   │                         STOP / FAIL
   └──────── RETRY / SUBMIT from stopped|error
```

Exact machine (this is the implementation, not a sketch):

```ts
import { assign, setup } from "xstate";

export type ChatEvent =
  | { type: "SUBMIT" }
  | { type: "TOKEN" }
  | { type: "DONE" }
  | { type: "FAIL"; error: string }
  | { type: "STOP" }
  | { type: "RETRY" };

export type ChatMachineContext = {
  threadId: string;
  lastError: string | null;
  abortable: boolean;
};

export const chatMachine = setup({
  types: {
    context: {} as ChatMachineContext,
    events: {} as ChatEvent,
    input: {} as { threadId: string },
  },
}).createMachine({
  id: "chatSession",
  initial: "idle",
  context: ({ input }) => ({
    threadId: input.threadId,
    lastError: null,
    abortable: false,
  }),
  states: {
    idle: {
      on: {
        SUBMIT: {
          target: "sending",
          actions: assign({ abortable: true, lastError: null }),
        },
      },
    },
    sending: {
      on: {
        TOKEN: { target: "streaming" },
        DONE: {
          target: "idle",
          actions: assign({ abortable: false }),
        },
        FAIL: {
          target: "error",
          actions: assign({
            lastError: ({ event }) => event.error,
            abortable: false,
          }),
        },
        STOP: {
          target: "stopped",
          actions: assign({ abortable: false }),
        },
      },
    },
    streaming: {
      on: {
        TOKEN: { target: "streaming" },
        DONE: {
          target: "idle",
          actions: assign({ abortable: false }),
        },
        FAIL: {
          target: "error",
          actions: assign({
            lastError: ({ event }) => event.error,
            abortable: false,
          }),
        },
        STOP: {
          target: "stopped",
          actions: assign({ abortable: false }),
        },
      },
    },
    stopped: {
      on: {
        SUBMIT: {
          target: "sending",
          actions: assign({ abortable: true, lastError: null }),
        },
        RETRY: {
          target: "sending",
          actions: assign({ abortable: true, lastError: null }),
        },
      },
    },
    error: {
      on: {
        RETRY: {
          target: "sending",
          actions: assign({ abortable: true, lastError: null }),
        },
        SUBMIT: {
          target: "sending",
          actions: assign({ abortable: true, lastError: null }),
        },
      },
    },
  },
});
```

### Binding to `useChat` (no status `useEffect`)

`lib/use-chat-session.ts` is the only place that imports both the hook and the machine.

| User / hook signal | Machine event | Hook call |
| --- | --- | --- |
| Composer submit or suggestion click | `SUBMIT` then `sendMessage({ text })` | `sendMessage` |
| First streamed part (`onData`) | `TOKEN` | none |
| `onFinish` | `DONE` | none |
| `onError` | `FAIL` | none |
| Stop button | `STOP` then `stop()` | `stop` |
| Retry button | `RETRY` then `regenerate()` | `regenerate` |

`onFinish` / `onError` / `onData` are `useChat` callbacks (event handlers, not effects). If the installed `ai` version names `onData` differently, use the documented stream-part callback on `UseChatHelpers`; if none exists, send `TOKEN` once from the first render where `status === "streaming"` is **not** acceptable (that is an effect in disguise). Fallback: omit `TOKEN` and treat `sending` as “in flight” until `DONE`/`FAIL`/`STOP`. The view may still show a streaming caret from hook `status === "streaming"` — that is derived render state, not a second source of truth for session phase.

New conversation does **not** add a machine event. Parent holds `threadId` in `useState`. Changing it remounts the session component with `key={threadId}` (reset-via-key). Conversation ids are `crypto.randomUUID()` (no `:`).

`useChat` must receive `threadId` only when defined. Never pass `id: undefined` (the wrapper already guards this; do not bypass it by calling `@ai-sdk/react` directly).

## Echo vs `XAI_API_KEY`

Decision is server-side in `onDirectMessage`, not in the client.

```ts
const apiKey = process.env.XAI_API_KEY;

if (!apiKey) {
  await thread.post(echoTextStream(message.text));
  return;
}

const history = await collectAiHistory(thread, message);
const result = streamText({
  model: xai("grok-4-1-fast-non-reasoning"),
  system: "You are a concise, helpful web assistant.",
  messages: history,
});
await thread.post(result.textStream);
```

Echo stream (`lib/echo.ts`) must be an `AsyncIterable<string>` so `thread.post` pumps tokens onto the Web adapter SSE response (same path as AI SDK `textStream`). Yield word-sized chunks with a short delay so the UI’s streaming state is observable.

xAI path:

- `import { streamText } from "ai"`
- `import { xai } from "@ai-sdk/xai"`
- `import { toAiMessages } from "chat/ai"` (not the deprecated re-export from `"chat"`)
- Collect with `for await (const msg of thread.allMessages)` (oldest first), cap at 20, then `await toAiMessages(collected)`
- Empty history → `[{ role: "user" as const, content: message.text }]`
- Use `textStream` (single-step generation, matches AGENTS.md). Do not introduce `ToolLoopAgent` or Chat SDK tools unless a later task asks.

```ts
export async function* echoTextStream(text: string): AsyncGenerator<string> {
  const body = `You said: ${text}`;
  const tokens = body.match(/(\s+|\S+)/g) ?? [body];
  for (const token of tokens) {
    yield token;
    await new Promise((resolve) => setTimeout(resolve, 16));
  }
}
```

```ts
import { createMemoryState } from "@chat-adapter/state-memory";
import { createWebAdapter } from "@chat-adapter/web";
import { xai } from "@ai-sdk/xai";
import { streamText, type ModelMessage } from "ai";
import { Chat } from "chat";
import { toAiMessages } from "chat/ai";
import { echoTextStream } from "./echo";

const BOT_NAME = "assistant";

export const bot = new Chat({
  userName: BOT_NAME,
  adapters: {
    web: createWebAdapter({
      userName: BOT_NAME,
      getUser: () => ({ id: "web-user", name: "You" }),
    }),
  },
  state: createMemoryState(),
});

bot.onDirectMessage(async (thread, message) => {
  const apiKey = process.env.XAI_API_KEY;
  if (!apiKey) {
    await thread.post(echoTextStream(message.text));
    return;
  }

  const collected = [];
  for await (const item of thread.allMessages) {
    collected.push(item);
    if (collected.length >= 20) break;
  }

  const history = await toAiMessages(collected);
  const messages: ModelMessage[] =
    history.length > 0
      ? history
      : [{ role: "user", content: message.text }];

  const result = streamText({
    model: xai("grok-4-1-fast-non-reasoning"),
    system: "You are a concise, helpful web assistant.",
    messages,
  });
  await thread.post(result.textStream);
});
```

```ts
"use client";

import { useChat } from "@chat-adapter/web/react";
import { useMachine } from "@xstate/react";
import { chatMachine } from "./chat-machine";

export function useChatSession(threadId: string) {
  const [snapshot, send] = useMachine(chatMachine, {
    input: { threadId },
  });

  const { messages, sendMessage, status, stop, error, regenerate } = useChat({
    api: "/api/chat",
    threadId,
    onData: () => {
      send({ type: "TOKEN" });
    },
    onFinish: () => {
      send({ type: "DONE" });
    },
    onError: (err) => {
      send({
        type: "FAIL",
        error: err instanceof Error ? err.message : "Request failed",
      });
    },
  });

  const sendText = (text: string) => {
    const trimmed = text.trim();
    if (!trimmed) return;
    if (snapshot.matches("sending") || snapshot.matches("streaming")) return;
    send({ type: "SUBMIT" });
    sendMessage({ text: trimmed });
  };

  const stopGeneration = () => {
    send({ type: "STOP" });
    stop();
  };

  const retry = () => {
    send({ type: "RETRY" });
    regenerate();
  };

  return {
    messages,
    status,
    snapshot,
    error,
    sendText,
    stopGeneration,
    retry,
  };
}
```

If TypeScript rejects `onData` on the installed `useChat` options, drop `onData` and keep `TOKEN` unused (sending → idle via `DONE` is already valid). Do not add `useEffect` to watch `status`.

```ts
"use client";

import { useState } from "react";
```
